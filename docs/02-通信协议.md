# 通信协议（上位机 ⇄ 下位机）

唯一的通道是 **UART 115200-8-N-1**。下位机用 UART0（USB 直连），所以插上就是
`/dev/ttyUSB0`（或 `/dev/ttyACM0`）。

## 1. 帧格式

```
@ | code | v1 | v2 | v3 #
│    │      └────┴────┴── 有符号整数，缺省为 0
│    └── 指令码
└── 帧头，收到即清空接收缓冲
```

- `@` 清缓冲，`#` 触发解析；解析用 `sscanf("|%d|%d|%d|%d")`，**返回 ≥2 个参数即有效**，
  所以 `@|5#`、`@|8|9|12#` 都能用（缺的参数当 0）。
- 单帧长度上限 63 字节，超长会被截断。

## 2. 上位机 → 下位机：指令表

以 `Serial.ChassisController` 的方法为准（左边是你会调用的方法）：

| 方法 | 报文 | 下位机行为 | 应答 |
| --- | --- | --- | --- |
| `go(val)` | `@\|1\|10\|60\|55#` | 两轮 PWM 直控前进，`val` 为 −100~100 百分比 | 无 |
| `distance(val, dis)` | `@\|6\|10\|100\|55#` | 走 `val×dis` 个编码器脉冲后停 | `@` |
| `cw()` / `ccw()` | `@\|2\|1\|±90\|0#` | **先前冲 1180 脉冲对齐路口中心**，再原地转 `v2` 度 | `@` |
| `turn(angle)` | `@\|2\|1\|{angle}\|0#` | 同上（带前冲） | `@` |
| `turn_pure(angle)` | `@\|3\|1\|{angle}\|0#` | 纯原地转 `v2` 度，无前冲 | `@` |
| `turn_all(angle)` | `@\|4\|1\|{angle}\|0#` | ⚠️ **忽略参数**，跑一套硬编码动作序列 | `@` |
| `stop()` | `@\|5\|0\|0\|0#` | 急停：立即停车、清空队列、中断当前动作 | `@` |
| `go_cross(speed, mult)` | `@\|7\|9\|01\|55#` | 以 `v1` 速度冲 `v2×1180` 脉冲，完成后**不清速度 PI** | `@` |
| `drive_steer(speed, angle)` | `@\|8\|9\|{angle}#` | 视觉 PID 差速巡线，`v2` 为视觉偏差量 | 无 |
| `set_camera_angle(angle)` | `@\|9\|{angle}\|0\|0#` | 低位/水平舵机 0–180° | 无 |
| `trigger_culvert_inspection()` | `@\|10\|0\|0\|0#` | 停车 → 双舵机扫描 → 上报 `Y_*` | 4 条 `Y_*` |
| `mini_adjust(dis)` | `@\|11\|10\|{dis}\|55#` | ⚠️ 见坑位表第 2 条 | 无 |
| `request_encoders()` | `@\|14\|0\|0\|0#` | 回一次累计脉冲 | `E:l,r` + `@` |
| `enable_telemetry(True)` | `@\|15\|1\|0\|0#` | 开启 100 ms 周期遥测 | `@` |
| `set_telemetry_interval(ms)` | `@\|17\|{ms}\|0\|0#` | 设置遥测周期 20–1000 ms | `@` |
| （无封装） | `@\|18\|{angle}\|0\|0#` | 高位摄像头俯仰舵机角度（标定用） | `@` |
| （无封装） | `@\|19\|{us}\|0\|0#` | 水平舵机原始脉宽 400–2600 µs（端点标定） | `@` |

> 注：指令 6 与 16 功能相同（`16` 是不带 PWM 直控的变体），上位机用 6 即可。

## 3. 下位机 → 上位机：上报报文

| 报文 | 含义 | 触发时机 |
| --- | --- | --- |
| `@` | 动作完成 | 指令 2/3/4/5/6/7/14/15/16/17/18/19 执行完毕 |
| `ERR:MOTION` | 动作失败 | 被打断、失联、或 7 s 超时 |
| `E:1234,1240` | 左右编码器累计脉冲 | 遥测开启后每 N ms，或指令 14 单次查询 |
| `Y_START` | 侦查开始，电机已锁 | 收到指令 10 后 |
| `Y_L` | 左侧扫描到位，请拍左 | 水平舵机扫到 180° 后 |
| `Y_R` | 右侧扫描到位，请拍右 | 水平舵机扫到 25° 后 |
| `Y_END` | 侦查结束，电机解锁 | 舵机归中后 |

## 4. 一次典型交互（路口直行）

```
上位机                                       下位机
  │  clear_pending_input()                     │   ← 丢掉上一动作残留的 @
  │ ──── @|7|9|01|55# ───────────────────────> │  开始冲过路口（编码器闭环）
  │                                            │  ...约 0.8 s...
  │ <───────────────────────────── "@\n" ───── │  冲过完成，速度 PI 保持不停
  │  （等 ACK_MIN_LATENCY=50ms，去抖 150ms）    │
  │ ──── @|8|9|{offset}# ────────────────────> │  无缝切入巡线，车不顿
```

## 5. 坑位表（都是我们真的踩过的）

| # | 坑 | 现象 | 怎么避 |
| --- | --- | --- | --- |
| 1 | `turn_all()` 发的是指令 4 | 车不按角度转，而是"转 15°→后退→转 26°→…"跑完一整套 | 单纯转向用 `turn_pure()`（指令 3）；`turn_all` 只在需要那套固定动作时用 |
| 2 | `mini_adjust()` 传 `v1=10` | 下位机只认 `v1==15` 进微调，传 10 会当成普通前进且**不自动停**——车会一直走 | 真要微调：手发 `@|11|15|{时长}\|55#`；或直接用 `distance()` |
| 3 | 指令 7 完成后不清速度 | 若之后不发任何指令，车会继续以原速度前进 | 指令 7 只在"立刻接指令 8 巡线"时用；否则补一条 `stop()` |
| 4 | 侦查期间电机被锁 | 侦查中发运动指令会被**静默丢弃**，上位机却以为发了 | 等 `Y_END` 之后再发运动指令 |
| 5 | `@` 应答有延迟/串位 | 上一动作的 `@` 被当成本次完成，导致提前发下一条 | 发指令前 `clear_pending_input()`，并保留 `ACK_MIN_LATENCY` + `ACK_DEBOUNCE` |
| 6 | 指令 14 会回两个报文 | `E:l,r` 和 `@` 前后脚到达，容易把 `@` 误当动作完成 | 解析时按前缀分流（主程序已这样做） |
| 7 | 遥测默认关闭 | 以为能读到 `E:`，其实一条都没有 | 需要时显式 `enable_telemetry(True)` |
| 8 | 失联看门狗 1.5 s | 上位机调试断点超 1.5 s，车会自己停车并锁死，之后指令无效 | 这是保护，不是 bug；重新发任意有效指令即解锁 |

## 6. RFID 协议（另一路串口）

RFID 是独立的 13.56 MHz 读卡器，走自己的 USB 串口（`RFID_PORT`），与底盘无关：

- 帧头 `7F`，28 字节一帧，含 `1A`/`91` 校验位与 XOR 校验和；
- 卡号取第 11 字节的**高 4 位**（`0x80` → 8 号点）；
- `raw_val == 0` 视为空白卡，直接过滤。

代码在 `src/rfid.py`，已做半帧拼接与滑窗重同步，掉字节不会卡死。
