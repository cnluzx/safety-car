# 改代码指南（改哪里）

按"我想做什么"索引，直接定位到文件和函数。

## 1. 想改赛道 / 地图

改 `src/topo_map.py` 的 `build_competition_track()`：

- **节点坐标**：函数里的 `positions` 字典（单位：米，仅用于计算边长与仿真，不影响实车）
- **道路连通**：`BASE_EDGES` 列表，`("A", "B")` 表示 A、B 之间有一条路
- **固定巡逻点**：`self.fixed_patrol_nodes = [f"N{i}" for i in range(1, 13)]`
- **涵洞可能出现的边**：`REFERENCE_GREEN_EDGES`（仅仿真用于随机撒点，实车靠视觉发现）
- **隧道段**：`TUNNEL_SEGMENTS`，把边映射到 T1–T4

改完先跑 `./run.sh --plan-only` 看路线是否合理，**不要直接上车**。

## 2. 想改走法（先直行还是先右转）

边上的动作序列在 `BASE_EDGES` 建图时写入，也可用 `add_edge(..., actions=[...])` 显式指定：

| 动作 | 下位机实际发的指令 |
| --- | --- |
| `FOLLOW_LINE` | `@\|8\|speed\|offset#` 巡线接管 |
| `FORWARD` | `@\|7\|9\|01\|55#` 冲过路口 |
| `LEFT` / `RIGHT` | `@\|2\|1\|±90\|0#` 前冲对齐 + 转向 |
| `U_TURN` | `@\|2\|1\|180\|0#` |
| `FOLLOW_CROSS` | `@\|7\|...` 冲过后立即巡线，不顿 |

## 3. 想改视觉巡线手感

三处，从上层到下层：

1. `FULL_MAP_KP` / `FULL_MAP_KD` / `FULL_MAP_MAX_ANGLE`（`FullMapConfig`）— 视觉 PID，先调这里
2. `src/line_detect.py` → `LineTracker.__init__` 里分割阈值、ROI 比例、路口判定宽度阈值
3. `lower-ESP/main/main.c` → `SPEED_KP` / `SPEED_KI` / `SPEED_MIN_PWM` — 轮速 PI

调巡线**必须用** `tests/test_line.py --drive`：它会画偏差波形，比盯着车看准得多。

`LineTracker` 有个容易忽略的接口：

```python
tracker.set_junction_mode("NORMAL" | "L" | "TUNNEL_EXIT")   # 切换路口判定剖面
```

`L` 用于 T 型/L 型路口（判定阈值不同），`TUNNEL_EXIT` 用于涵洞出口（更容易误判为路口）。
主程序会根据当前所在路段自动切换（`_expected_junction_mode()`），改赛道时要一起改。

## 4. 想换视觉模型

见 [models/README.md](../upper-PI/models/README.md)。代码侧只需保证文件名不变，
或设 `DEEPLAB_MODEL` / `YOLO_*` 环境变量。输入尺寸改了就同步改 `line_detect.py` 里的
`input_width` / `input_height`。

## 5. 想改侦查流程（扫视角度、时长）

- **硬件动作时序**在下位机：`lower-ESP/main/main.c: run_culvert_inspection()`。
  改了它就要同步改上位机等待逻辑（上位机在等 `Y_L` / `Y_R`）。
- **上位机侧**：`src/full_map_walk_test.py: _run_culvert_scan()`，控制触发时机、超时
  （`CULVERT_SCAN_TIMEOUT`）与拍照落盘。
- **判定灵敏度**：`src/Culvert_detect.py` 的 `consistency_threshold`（亮度一致性）与
  `edge_threshold`（纹理），对应环境变量 `CULVERT_BRIGHTNESS_THRESHOLD`。

## 6. 想加新指令（新硬件）

三步，缺一不可：

1. `lower-ESP/main/main.c` → `parse_and_execute()` 加一个 `case`，做完回 `@`（或先不回）
2. `upper-PI/src/Serial.py` → `ChassisController` 加一个方法发对应报文
3. `docs/02-通信协议.md` 补一行（别让下一届再猜）

**注意**：`parse_and_execute` 跑在 `motion_task` 里，是串行队列。任何一个 case 里做
长阻塞（比如等传感器）都会卡住后面所有指令。长动作请在 case 内部自己轮询取消标志
（参考 `wait_for_pulses_mode`）。

## 7. 想改安全策略

| 想改什么 | 位置 |
| --- | --- |
| 失联多久停车 | `LINK_TIMEOUT_MS`（默认 1500 ms） |
| 侦查期间是否锁电机 | `motion_locked()` / `g_inspection_active` |
| 单动作超时 | `MOTION_TIMEOUT_TICKS`（默认 700 tick = 7 s） |
| 相机断流保护 | `FullMapConfig.camera_stale_timeout`、`road_stale_timeout` |
| 连续丢帧停车 | `FULL_MAP_MAX_CAMERA_MISSES`（默认 10 帧） |

改完必须做一次"拔线测试"：运行中拔掉相机、拔掉底盘串口，确认车能停。

## 8. 代码风格约定（当时没严格执行，建议下一届统一）

- 下位机：宏定义集中在文件顶部，`#define` 前面带 `// ── 分组 ──` 注释
- 上位机：模块级常量用大写下划线，参数尽量走环境变量而不是硬编码
- 中文注释写"为什么这么做"，英文注释写"做了什么"（当时混用了，别学）
- 所有串口命令的字符串拼接集中在 `Serial.py`，不要在业务代码里手写 `@|...|#`
