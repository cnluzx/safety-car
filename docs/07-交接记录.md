## 4. 遗留问题（按优先级）

### 高

1. **里程计没接进主流程**。`odometry.py` 代码完整、主程序也 `update_encoders()` 了，
   但**从未调用 `chassis.enable_telemetry(True)`**，下位机默认遥测关闭 → 收不到 `E:` →
   位置恒为 0。当前靠 RFID + 视觉路口计数导航，能用但一丢 RFID 就退化成"盲走"。
   修法：启动时开遥测（`@|15|1|0|0#`），并给 odometry 加上"超时无数据则降权"。
2. **`Serial.mini_adjust()` 是坏的**（`v1=10` 不触发微调，会变成持续前进）。
   要么改成 `@|11|15|{时长}|55#`，要么删掉这个方法免得误用。
3. **`Serial.turn_all()` 语义误导**（发指令 4，跑固定序列）。建议改名为 `run_fixed_sequence()`。

### 中

4. `main.py`、`test_map.py` 是被取代的旧实现，仍留在 `tests/` 里。价值是"另一种架构的参考"，
   但和 `src/full_map_walk_test.py` 高度重复（1600–2000 行）。建议下一届确认不再需要后删除。
5. `tests/test_yolo.py`、`tests/test_deeplabv3.py` 缺模型，跑不起来（见 models/README.md）。
6. 下位机 `main.c` 800 行单文件，可拆 `motor/servo/pid/protocol` 四个模块。
7. 下位机速度 PI 在 `portENTER_CRITICAL` 临界区内做浮点运算，关中断时间偏长，
   建议临界区只做快照拷贝、计算放到区外。
8. `topo_map.py` 的赛道坐标是手填的，`BASE_EDGES` 与真实场地靠人工对齐，换场地要重画。

### 低

9. 中文文件名 `docs/*.md` 在部分 Windows 环境 clone 后可能乱码，必要时改英文名。
10. `upper-PI` 目录名里的 `PI` 有误导（实际是香橙派 RK3588），但为免破坏引用未改名。

## 5. 给下一届的三条建议

1. **先把通信协议吃透**（`docs/02-通信协议.md`），比读 2000 行主程序有用得多。
   两个人分别负责上/下位机时，协议就是唯一的契约。
2. **善用 `--plan-only` 和 `tests/`**。我们花在"上车试一次才发现规划错"的时间太多了，
   这些脚本就是为此写的。
3. **保留失联保护和急停**。它们是比赛现场唯一能救你的东西，改代码时别绕过。
