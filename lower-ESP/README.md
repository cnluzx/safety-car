# ESP32-S3 智能安防小车 · 下位机（底盘控制）

上位机（树莓派）通过 UART 下发指令，本工程运行在 ESP32-S3 上，负责底盘运动控制、
编码器闭环、舵机云台、串口协议解析与失联保护。

## 1. 平台与工具链

| 项目 | 说明 |
| --- | --- |
| 芯片 | ESP32-S3（2 MB Flash，无 PSRAM） |
| 框架 | ESP-IDF v5.5.2 + FreeRTOS |
| 通信 | UART0（USB 直连上位机），115200-8-N-1 |
| 构建 | CMake / idf.py |

## 5. 串口协议

- 帧格式：`@|code|v1|v2|v3#`
- `@` 清空缓冲，`#` 触发解析；参数为有符号整数
- 最少可只带 code（`@|5#` 也可解析，`sscanf` 返回 ≥2 即有效）

### 5.1 指令表

| code | 功能 | v1 | v2 | v3 | 应答 |
| --- | --- | --- | --- | --- | --- |
| 1 | 前进（PWM 直控） | 速度 −100~100 | — | — | 无 |
| 11 | 前进 / 定时微调 | 速度；=15 时进入微调 | 微调时长（×10 ms） | — | 无 |
| 2 | 路口对齐后转向 | 固定前冲 10 | 转角（>0 顺 / <0 逆） | — | `@` |
| 3 | 原地转向（无前冲） | — | 转角（>0 顺 / <0 逆） | — | `@` |
| 4 | 固定动作序列 | — | — | — | `@` |
| 5 | 急停（立即生效，不入队） | — | — | — | `@` |
| 6 | 定距前进 | 目标轮速 | 脉冲系数 | — | `@` |
| 7 | 冲过路口（完成后交给巡线） | 目标轮速 | 脉冲系数 | — | `@` |
| 8 | PID 巡线差速 | 基础速度 | 角度修正量 | — | 无 |
| 9 | 水平舵机角度 | 0–180 | — | — | 无 |
| 10 | 视觉触发涵洞侦查 | — | — | — | `Y_*` 序列 |
| 14 | 单次查询编码器 | — | — | — | `E:l,r` + `@` |
| 15 | 遥测开关（默认关） | 1 开 / 0 关 | — | — | `@` |
| 16 | 定距前进（同 6） | 目标轮速 | 脉冲系数 | — | `@` |
| 17 | 遥测间隔 | 20–1000 ms | — | — | `@` |
| 18 | 俯仰舵机角度（标定用） | 0–180 | — | — | `@` |
| 19 | 水平舵机原始脉宽（标定用） | 400–2600 µs | — | — | `@` |

### 5.2 上位机 ← 下位机上报

| 报文 | 含义 |
| --- | --- |
| `@` | 动作完成应答 |
| `ERR:MOTION` | 动作失败或超时（7 s 上限） |
| `E:left,right` | 左右编码器累计脉冲 |
| `Y_START` / `Y_L` / `Y_R` / `Y_END` | 侦查流程的四个阶段信号 |

### 5.3 指令说明

- **2**：先以速度 10 前冲 `ENC_FWD_TO_CENTER` 脉冲对齐路口中心，再原地转向。
- **3**：纯原地转向，左右轮反向等量，按编码器累计脉冲定角度。
- **4**：硬编码的连续动作（15° → 后退 → 26° → 后退 → 30° → 后退 → 90° → 后退），
  用于固定场地动作，角度与后退距离均为常量。
- **6 / 16**：`v1 × v2 = 目标脉冲数`，两轮同向取平均判定完成。
- **7**：冲过路口后**不清速度 PI**，ACK 发出即由巡线（指令 8）无缝接管。
- **8**：视觉 PID 输出左右轮目标差速，速度 PI 再按编码器 10 ms 脉冲数分别补偿左右 PWM。
- **11 的 `v1=15`** 是历史约定：既表示速度 15，也表示进入定时微调模式。

## 6. 控制参数

```c
// 编码器标定
ENC_FWD_TO_CENTER  1180   // 指令 2 前冲脉冲（对齐路口中心）
ENC_TURN_PER_V2      13   // 每 1° 转角对应脉冲数
ENC_CROSS_PER_V2   1180   // 指令 7 冲过路口的脉冲当量
TURN_SPEED_NORMAL     8   // 指令 2 转向轮速
TURN_SPEED_PURE       8   // 指令 3 转向轮速

// 视觉巡线 PID（指令 8）
PID_KP 0.12  PID_KI 0.004  PID_KD 0.25
PID_INTEGRAL_MAX 30.0      PID_OUTPUT_MAX 50.0
// 执行指令 2/3/5/7 后自动复位积分

// 左右轮速度 PI
SPEED_TARGET_SCALE 1.0   // 指令速度 → 脉冲/10ms，需按实车标定
SPEED_TARGET_MAX  45.0   // 单轮目标限幅
SPEED_KP 0.65  SPEED_KI 0.04  SPEED_INTEGRAL_MAX 300.0
SPEED_FEEDFORWARD 1.0    SPEED_MIN_PWM 11.0   SPEED_FILTER_ALPHA 0.35

// 舵机角度
SERVO_HOME_ANGLE     105  // 水平舵机归中/初始角度
DETECT_SERVO_NORMAL    0  // 俯仰舵机常态
DETECT_SERVO_CULVERT  90  // 侦查时俯仰角度

// 超时
MOTION_TIMEOUT_TICKS 700  // 单动作 7 s 上限（10 ms/tick）
LINK_TIMEOUT_MS     1500  // 上位机失联判定
LINK_CHECK_PERIOD_MS 100
```

## 7. 编码器

- ESP32 PCNT 外设硬件正交解码（×4），10 µs 毛刺滤波
- 左/右单元独立计数，读后清零（`encoder_read_left/right`）
- `encoder_task` 每 10 ms 读取一次（100 Hz），与 STM32 版 TIM1 10 ms 中断行为一致
- 累计值 `g_enc_left_total / g_enc_right_total` 在临界区内更新，避免 64 位跨任务撕裂

## 8. FreeRTOS 任务

| 任务 | 栈 | 优先级 | 职责 |
| --- | --- | --- | --- |
| `uart_rx_task` | 4096 | 10 | 收帧、解析、入队；急停直接就地处理 |
| `motion_task` | 3072 | 8 | 顺序执行运动/转向/舵机指令，避免阻塞串口 |
| `encoder_task` | 4096 | 6 | 10 ms 读编码器、跑速度 PI、按需上报遥测 |
| `link_watchdog` | 2560 | 9 | 100 ms 检查通信超时，失联即停车锁死 |

指令队列深度 12；串口发送用互斥量保护，避免多任务报文交叉。

## 9. 安全机制

| 机制 | 说明 |
| --- | --- |
| 急停优先 | 指令 5 不入队：立即停车、清空队列、置取消标志 |
| 失联停车 | 1500 ms 无有效指令 → 停车 + 清空队列 + 置 `g_link_lost` 锁死电机 |
| 侦查电机锁 | `g_inspection_active` 期间拦截所有非零速度指令 |
| 动作可中断 | 定距/转向每 10 ms 检查取消与安全标志，可被急停提前终止 |
| 输入保护 | 舵机角度钳制 0–180°；零速度或零脉冲动作直接返回 |

## 10. 编译与烧录

```bash
# 需要 ESP-IDF v5.5.2 环境（idf.py 已加入 PATH）
idf.py set-target esp32s3
idf.py build
idf.py -p <COMx> flash monitor
```

`build/` 与 `sdkconfig` 不入库，由 `sdkconfig.defaults` 生成。

## 11. 已知限制 / 后续可改进

- `main.c` 约 800 行单文件，可按 `motor` / `servo` / `pid` / `protocol` 拆分
- 速度 PI 在 `portENTER_CRITICAL` 临界区内做浮点运算（关中断时间偏长），
  建议临界区内只拷贝快照，浮点计算放到临界区外
- 指令 4 的动作序列是硬编码常量，建议改为表驱动
- 指令 1 与 11 语义重叠（`v1=15` 触发微调是隐式约定），建议改为独立指令码
- 涵洞识别由上位机视觉负责，本工程只提供触发与扫描时序
