# 智能安防巡逻小车 · 参赛项目代码

一个能从出发区自主巡线、识别涵洞并侦查拍照、绕开障碍、最后自动返回的轮式机器人。
比赛任务是**全地图巡检**：覆盖所有道路 → 经过全部固定点 → 侦查随机分布的涵洞 → 回到出发区。

> 这份仓库是**交接用参考代码**。代码是当时比赛现场跑通的版本，保留了真实调参痕迹，
> 有已知缺陷（见 [调试与排故](docs/06-调试与排故.md) 和 [交接记录](docs/07-交接记录.md)）。
> 目的是让下一届能看懂、能改、能避开我们踩过的坑，而不是一份"完美示例"。

## 1. 30 秒认识这个系统

```
        上位机（香橙派 5 Pro / RK3588）                        下位机（ESP32-S3）
 ┌──────────────────────────────────────────┐   UART 115200   ┌──────────────────────┐
 │  摄像头 ×2 ──> RKNN NPU 推理              │  @|code|v1|v2|v3#│  电机 PWM + 编码器    │
 │    巡线摄像头(低) / 涵洞摄像头(高)         │ ───────────────> │  舵机云台 ×2          │
 │                                          │ <─────────────── │  速度 PI / 定距闭环    │
 │  拓扑地图 → 导航规划 → 决策               │   @ / E:l,r      │  失联保护 / 急停       │
 │  RFID 绝对定位 + 编码器里程计              │   Y_START/Y_L…   │                      │
 │  OLED 状态显示 + 语音播报                 │                  │                      │
 └──────────────────────────────────────────┘                  └──────────────────────┘
              "想怎么走、看到什么"                                  "怎么动、走了多远"
```

分工一句话：**上位机负责"看"和"想"，下位机负责"动"和"记得走了多远"**。
两者只通过一串 ASCII 指令通信，所以可以独立调试、独立替换。

## 3. 三分钟跑起来（先跑通再读懂）

```bash
# ── 下位机 ──
cd lower-ESP
idf.py set-target esp32s3
idf.py build flash monitor      # 串口应打印 "Chassis System Online."

# ── 上位机 ──
cd upper-PI
pip install -r requirements.txt # rknnlite 需要 Rockchip 官方 wheel，见部署文档
cp .env.example .env            # 按实际设备改 CHASSIS_PORT / RFID_PORT / 摄像头编号
./run.sh --plan-only            # ① 只算路线，不碰硬件（验证规划器）
./run.sh                        # ② 整车运行
```

`--plan-only` 是最有用的第一步：不初始化摄像头、串口和模型，纯离线把这次要走的
完整节点路线打出来。规划器改完先跑它，能省掉大量上车的往返。

## 5. 上车前必看的 5 个坑

1. **串口不是固定名字**。默认 `/dev/ttyUSB0`，接了多个 USB 串口时会变成 `ttyUSB1`/`ttyACM0`，
   用 `CHASSIS_PORT` / `RFID_PORT` 环境变量覆盖。
2. **摄像头编号每次开机可能变**。用 `v4l2-ctl --list-devices` 确认，再设 `NAV_CAMERA` / `CULVERT_CAMERA`。
3. **指令 4 会跑一套固定动作序列**（转 15°→后退→转 26°→…），不是"转向指定角度"。
   `Serial.turn_all()` 发的是指令 4，慎用；单纯转向请用 `turn_pure()`（指令 3）。
4. **`mini_adjust()` 目前不生效**。它发 `@|11|10|…`，而下位机只有在 `v1==15` 时才进入定时微调，
   传 10 会走成"持续前进"。详见协议文档的坑位表。
5. **遥测默认关闭**，主程序没有调用 `enable_telemetry()`，所以 `odometry` 其实收不到编码器数据，
   位置恒为 0。当前导航依赖 RFID + 视觉路口判断——这是能用但脆弱的方案，见交接记录。
